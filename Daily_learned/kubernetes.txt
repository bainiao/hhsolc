1. 基本概念
    1. 开发，运维，测试，架构
    2. 管理containers，pod，service，volume，通过配置文件管理
        高可用：程序在长时间可靠运行，自我重建，自我修复，自我扩展，自我收缩
        弹性：根据负载自动伸缩
        微服务：将一个大的应用拆分成多个小的服务，每个服务负责一个独立的业务功能，服务之间通过接口进行通信
        容器化：将应用程序及其依赖项打包到一个标准化的单元中，以便在任何环境中运行
    3. kubernetes是容器编排工具，容器是轻量级，可移植，自给自足的软件包，容器化应用程序可以在几乎任何地方运行，而无需修改
    4. kubernetes是开源的，由google开发，并捐赠给CNCF
    5. node => 物理机、虚拟机
    6. pod => 一个或多个容器，共享网络和存储，可以看作是容器的一个逻辑单元
    7. service => pod的抽象，提供网络和负载均衡，可以看作是pod的访问入口
    8. volume => 存储卷，用于持久化存储数据
    9. namespace => 命名空间，用于隔离资源，可以看作是虚拟集群
    10. label => 标签，用于标识资源，可以看作是资源的属性
    11. annotation => 注释，用于存储元数据，可以看作是资源的描述
    12. Ingress => 入口，用于管理外部访问集群内部的服务，可以看作是集群的入口网关
    13. ConfigMap => 配置管理，用于管理应用程序的配置信息
    14. Secret => 密钥管理，用于管理应用程序的敏感信息，如密码、密钥等
    15. Deployment: 无状态应用部署
    16. StatefulSet: 有状态应用部署
2. Kubernetes架构
    1. master节点：负责管理集群，包括调度、监控、日志等
    2. worker节点：负责运行容器，包括创建、删除、更新等
    3. etcd：分布式键值存储，用于存储集群的配置信息
    4. kube-apiserver：提供集群的API接口，用于管理集群资源
    5. kube-controller-manager：负责管理集群的控制器，包括节点控制器、副本控制器等
    6. kube-scheduler：负责调度容器到合适的节点上运行
    7. kubelet：负责管理节点上的容器，包括创建、删除、更新等
    8. kube-proxy：负责管理节点的网络，包括负载均衡、网络转发等
